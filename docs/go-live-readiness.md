# Go-Live Readiness

## Current Answer

The app is targeted for **Beta v0.1.0**, but the go-live direction has changed.
The hosted Python/SQLite public-access path is paused because it requires more
maintenance than desired.

New direction:

- GitHub Pages static dashboard
- GitHub Actions scheduled/manual data generation
- repo files as editable source inputs
- static JSON outputs consumed by the browser
- no always-on Python server, hosted SQLite, Basic Auth, reverse proxy, or
  backup service

See `docs/static-github-pages-remake.md`.

The app should not be presented as a fully validated research platform. With
free/open data, "accurate, reliable, credible, and validated" must mean:

- latest available source fetches are interactive and freshness-visible
- source, timestamp, confidence, limitations, and missing data are visible
- provider data is clearly separated from reviewed/manual/source-linked rows
- primary/report-level review is available for important fields
- missing data stays missing
- no recommendation or standalone valuation verdict logic is added

## Public Access Direction

Recommended first public setup:

- GitHub Pages serves the static app.
- GitHub Actions builds data pre-open and post-close/evening on weekdays.
- Manual `workflow_dispatch` supports operator-triggered refresh.
- Generated JSON includes source timestamps, source errors, stale/missing-data
  states, and workflow metadata.
- Watchlist and manual review state are stored in repo files under `data/`.
- Watchlist edits take effect on the next scheduled/manual generation run.

Avoid for the first MVP:

- direct repo writes from public Pages JavaScript
- browser-side personal access tokens or write tokens
- GitHub OAuth/GitHub App write flows
- serverless write proxies
- always-on backend hosting

## Static Data Expectations

Interactive/on-demand pieces need to become generated static data:

- fundamentals and own-history snapshots generated by Actions
- Watchlist overview generated from repo inputs plus fetched sources
- NewsWeb/event monitoring generated on schedule/manual dispatch
- Technical indicators generated from Oslo Screener `latest.csv`
- manual/source-linked consensus rows moved to repo files
- manual/source-linked event rows moved to repo files
- reviewed/source-linked sector KPI inputs moved to repo files
- quarterly statement primary-report review tracking moved to repo files

Before public MVP, the static remake should make generation state clear:

- show last successful generation
- show source timestamps, stale states, and errors
- show scheduled/manual workflow run metadata
- keep conservative rate limits for NewsWeb/yfinance calls
- keep NewsWeb digest screening-grade and source-linked

Repo planning completed for this step:

- `docs/static-github-pages-remake.md` records the static architecture,
  watchlist-editing options, scheduled NewsWeb direction, first sprint scope,
  open decisions, and copy/paste prompt.

## Data Quality Boundary

The MVP can be credible, but not authoritative.

Free/open data remains screening-grade. The app should keep using source
quality, timestamps, confidence, limitations, and missing-data gates as the
trust model.

Critical fields that need stronger trust should move through source-linked or
manual review paths:

- quarterly statement periods: primary company-report review rows
- consensus/targets: provider-row versus manual/source-linked source rows
- peer groups: draft/reviewed/trusted curation
- sector KPIs: reviewed/trusted source-linked inputs
- events: NewsWeb source rows plus manual/source-reviewed significant events

Do not infer peer groups, sector KPIs, sector index/proxy rows, NAV/fleet,
EBIT/kg, backlog, ROE/CET1, LTV/WAULT, or statement history from generic sector
labels.

## Beta v0.1.0 End State

Beta v0.1.0 is release-ready when:

- the app headline clearly shows `Beta v0.1.0`
- public GitHub Pages URL works from another device
- generated JSON data loads without a backend server
- scheduled/manual GitHub Actions data build passes
- generated data shows source timestamps, stale/error/missing states, and
  workflow metadata
- watchlist edit path is explicit: GitHub web-editor link or app-generated
  draft/export diff for repo file changes
- NewsWeb rows/digest are generated by scheduled/manual Actions, not promised as
  live on-demand backend results
- Watchlist, Fundamentals, Own history, Benchmarks, News/Events, Technical
  indicators, Sources, and the separate RSI14 screener work from another device
- no recommendation logic or standalone valuation verdict labels have been added

Goal: reduce avoidable operational risk before you use the MVP for a while.

Tasks:

- run a complete GitHub Pages smoke test from another device
- check mobile/tablet usability for tables and detail panels
- document a simple beta operating routine
- document static data regeneration and rollback steps using git history and
  GitHub Actions runs

Exit criteria:

- external device review passes
- regeneration and rollback steps are documented and tested
- known-good generated data state exists in git history or Pages artifact
- beta caveats are documented
- MVP is ready for real use and feedback collection

## Not In Go-Live Scope Unless Explicitly Added

- buy/sell/hold recommendation logic
- cheap/expensive/fair/neutral valuation labels
- public unauthenticated access
- automated broker-estimate scraping
- automated primary-report value extraction
- live/on-demand backend NewsWeb search
- multi-user permission model beyond a shared access gate
- portfolio execution or transaction features

## Suggested Next Sprint

Start Sprint 1: Static GitHub Pages Remake.

Do not broaden data automation or valuation logic until the static Pages version
is loading generated data, showing source quality clearly, and verified from
another device.
