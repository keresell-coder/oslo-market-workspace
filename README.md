# Oslo Stock Web App

Local-first Oslo Bors research workspace, currently moving toward a public
static GitHub Pages beta generated by GitHub Actions.

The Watchlist is the synthesis view. Deeper tabs hold the evidence: source
detail, fundamentals, own-history context, technical indicators, peer context,
consensus/source rows, and events.

## Guardrails

- No buy/sell investment advice.
- No standalone cheap/expensive/fair/neutral valuation labels.
- Relative valuation requires peers, sector, own history, source quality, and
  missing-data context.
- Free data is screening-grade only. Show source, timestamp/freshness,
  confidence, limitations, and missing data clearly.
- Missing data stays missing.
- Technical BUY/SELL/BUY-watch/SELL-watch labels are external screener source
  labels, not app recommendations.
- Public GitHub Pages JavaScript must not contain GitHub write tokens.

## Run Locally

```bash
python3 app/server.py
```

Default URL:

```text
http://127.0.0.1:8765
```

After each sprint or user-visible update:

```bash
scripts/open_in_safari.sh
```

If the port is busy, stop the stale Python process or use another local port.
During development, `8768` has often been used.

## App Surface

- **Start**: beta warning, source/metric summary, operator checklist, limits.
- **Watchlist**: compact synthesis row per company; detail drawers hold dense
  source/caveat text.
- **Fundamentals**: yfinance/provider fields, source-gated multiples,
  consensus/source rows, validation notes.
- **Own history**: price range context, local snapshot trends, strict yfinance
  quarterly statement rows, primary-report review tracking.
- **Technical indicators**: Oslo Screener `latest.csv` data, with explicit
  missing-coverage rows.
- **Benchmarks**: peer groups, curation status, peer notes, sector benchmark
  components, and reviewed/source-linked KPI slots.
- **News/Events**: NewsWeb rows plus manual/source-reviewed events and digest.
- **RSI14 screener**: separate embedded dashboard; do not edit screener repos
  unless explicitly requested.
- **Sources**: source quality and limitations.

## Data State

- Displayed EV/EBITDA is computed from yfinance enterprise value, TTM EBITDA,
  and FX when inputs pass gates. Raw provider EV/EBITDA is retained only as
  audit data.
- Displayed TTM P/E, forward P/E, P/B, P/S, EV/revenue, EV/EBITDA, and dividend
  yield carry source/method/input metadata where feasible.
- P/NAV and EV/EBIT remain intentionally unavailable until source-linked inputs
  exist.
- Quarterly statement history uses dated yfinance quarterly tables only; current
  summary fields are not used as proxies.
- Peer statuses are local curation markers: `missing`, `draft`, `reviewed`,
  `trusted`. They do not create valuation verdicts.
- Sector benchmark components are explicit: Oslo peer group, international peer
  group, and optional sector index/proxy. Nothing is inferred from sector labels
  alone.
- NewsWeb digest remains on demand locally and generated/static in Pages mode.
- Current generated technical coverage has 14 covered watchlist rows and one
  explicit missing-from-latest-CSV row, `NORBT.OL`.
- Fundamental frameworks remain a future sprint. The external `oslo-quant`
  framework screener is nearly ready but should not be integrated here until its
  output contract and final tweaks are reviewed.

## Editing Workflow

Static Pages is read-only. Watchlist and peer edits should go through reviewed
repo changes:

1. Edit YAML under `data/` on a `codex/` branch.
2. Validate schema with `python3 scripts/validate_static_inputs.py`.
3. Regenerate static JSON.
4. Open and merge a PR.
5. Run or observe the static-data workflow.
6. Verify the public Pages URL, manifest timestamp, and affected rows.

Peer groups use the same path through `data/peer_groups.yml`. Validation now
requires approved statuses/roles, no duplicate peers inside a group, and exactly
one focus company per peer group.

## Verification

For code changes, run:

```bash
python3 -m py_compile app/server.py scripts/build_static_site_data.py
python3 -m py_compile scripts/validate_static_inputs.py
python3 scripts/validate_static_inputs.py
node --check app/static/app.js
node --check docs/app.js
```

When the local server is running, also smoke-check:

```bash
curl -s http://127.0.0.1:8765/api/watchlist-overview | python3 -m json.tool
curl -s "http://127.0.0.1:8765/api/fundamentals?symbols=MOWI.OL" | python3 -m json.tool
curl -s "http://127.0.0.1:8765/api/technical-indicators?universe=watchlist" | python3 -m json.tool
curl -s "http://127.0.0.1:8765/api/event-monitoring" | python3 -m json.tool
```

Use the in-app browser for UI changes. Verify Watchlist, Fundamentals, Own
history, Benchmarks, News/Events, Technical indicators, Sources, and RSI14
screener when relevant.
